# 審査用アクセス 実機テスト仕様書

作成日 2026年11月28日
対象 YomiPalette Android / `codex/play-review-access`
実施状況 未実施。各項目の結果は実施後に記録する。

## 1. 目的と合格条件

Google アカウントでのアプリ内ログインと購入の操作を行わずに、審査担当者が制限対象の機能を確認できることを実機で検証する。

次の条件をすべて確認して合格とする。

- 共通トークンによる初回登録後、再起動しても審査用アクセスを利用できる。
- 試聴、MP3 生成、TXT・EPUB・PDF の取り込み、保存、共有、生成再開が利用できる。
- 発行済み権利の72時間以内はオフラインで利用でき、期限後は通信復旧によって更新される。
- 更新用資格情報の失効を受信した端末では審査用アクセスが解除される。
- 試用開始日、試用期限、購入済みの権利が審査用アクセスの開始・終了・失効によって変化しない。
- 日本語・英語・簡体字中国語の案内と、Play Console に登録する英語の操作手順で目的の機能まで到達できる。

既存の自動テストの成功は参考情報として記録する。実機試験の結果は本書に個別に記録する。

## 2. 実施前の準備

### 対象ビルドとサーバー

対象アプリの表示バージョン、ビルド番号、Git コミット、未コミット変更の有無、APK の SHA-256 または Play 配布版の識別情報を記録する。現在のソースのバージョンは `0.2.11+19`。実施時には対象ビルドで再確認する。

Worker の配備、Secret の登録、D1 マイグレーション、アプリの公開鍵と接続先の指定を済ませる。具体的な設定方法は [導入手順](play_review_access.md) を参照する。

| 確認項目 | 実施前に確認する内容 |
| --- | --- |
| 接続先 | `YOMIPALETTE_REVIEW_ACCESS_URL` が検証対象 Worker の HTTPS `/review` を指す |
| 署名検証 | Worker の署名鍵に対応する公開鍵と key ID が対象ビルドに指定されている |
| D1 | `0003_review_access.sql` が対象 DB に適用されている |
| 認証 | `REVIEW_ACCESS_TOKEN` に十分にランダムなトークンを設定済み |
| 回数制限 | Worker に IP 制限と更新用資格情報の制限の binding がある |
| 時刻 | 端末の日時の自動設定を有効化し、サーバーとの大幅な時刻差がない |
| 試用・購入 | 権利の独立性を試すビルドは試用・購入の検証先も正常に設定されている。QA による無条件開放は無効 |

一般ユーザー向けの権利やサービスに影響する失効・障害・鍵変更の操作は、専用の検証 Worker・DB で実施する。Play 内部テスト配布版でも、審査用接続先と公開鍵を揃える。

### 端末と初期状態

| 呼称 | 用途と初期状態 |
| --- | --- |
| 端末A | 主試験端末。実際の Android 実機。試用登録なし、購入権利なしのクリーン状態から開始 |
| 端末B | 別の Android 実機。同じトークンの再利用と、片方だけの失効を確認 |
| 試用状態 | 有効な試用登録があり、開始日・終了日を記録済み。専用の状態として準備 |
| 購入状態 | Play のテスト購入で `full_access` が検証済み。復元も確認済み。専用の状態として準備 |
| 期限切れ試用状態 | 試用が終了し、購入権利もない状態。試用中への復帰が発生しないことを確認 |

試用・購入の試験では同じ実機を順番に使用してよい。その場合は各ケース開始時に権利状態を再確認する。Google Play からのインストールに使う端末側の Google アカウントについても記録する。

審査用認証は専用トークンと更新用資格情報で行う実装である。Google Play にログインした端末でも、アプリ内 Google ログインを操作していないことを確認する。Google Play 未ログイン端末の確認は、APK を使用した追加ケース RA-25 で扱う。

### 試験データと TTS

- TXT は UTF-8 の短い文章と、複数ユニットに分割できる長文を用意する。
- EPUB は複数章を持つテキスト入りのファイルを用意する。
- PDF はテキスト入りの複数ページを用意する。抽出可能な章・ページと文章を事前に把握する。
- 各ファイルに期待する章・ユニット数、冒頭の文章、分割設定を記録する。
- オフラインの試聴と MP3 生成には、音声データをダウンロード済みの Android 端末 TTS を使用する。
- Edge TTS、Azure Speech、Google Cloud TTS はオンラインで確認する。Azure と Google Cloud 用には検証専用の資格情報と利用枠を準備する。
- 出力先は検証用フォルダーを作成し、保存権限を付与する。元ファイルと生成ファイルの保存場所を記録する。

## 4. 基本操作

### RA-01 初回登録と全機能への到達

前提は、端末Aにアプリをクリーンインストール済みで、オンライン、試用・購入権利なし。

1. アプリを起動し、「このアプリについて」→「Google Play 審査用」を開く。
2. 有効な共通トークンを入力して「審査用アクセスを有効にする」を押す。
3. ホームへ戻り、試験用 TXT を読み込み、音声・ユニットを選択する。
4. 試聴し、MP3 を生成して再生する。

期待結果は「審査用アクセス」が表示され、アプリ内 Google ログインと購入の操作を行わずに試聴・生成が完了すること。購入ボタンと試用ログインの案内が審査用アクセス中に表示されず、初回入力欄は更新・終了の操作に切り替わること。D1 に端末Aの登録が作られること。

### RA-02 入力誤りと再試行

前提は、登録のない端末。空欄、誤ったトークンをそれぞれ送信し、その後に正しいトークンで登録する。

期待結果は、誤入力では権利が付与されず、アプリが操作可能な状態を保つこと。正しいトークンで再試行すると登録できること。認証失敗後のトークン入力欄は空になるため、再入力して確認する。

### RA-03 再起動・強制終了・端末再起動

RA-01 の直後に、アプリの終了と再起動、Android 設定からの強制停止後の再起動、端末再起動を順番に行う。各操作後に TXT の試聴・生成を確認する。

期待結果は、共通トークンの再入力を求められず、オンライン更新後も審査用アクセスが維持されること。

### RA-04 ファイル形式・保存・共有

審査用アクセス中に TXT、EPUB、PDF をそれぞれ取り込み、章・ページと選択ユニットを確認する。ユニットを指定して生成し、選択フォルダーへの保存、生成ファイルの再生、共有を行う。フォルダーを指定しない保存・共有も確認する。

期待結果は、事前に記録した章・ページ・文章と対応し、生成対象と保存先が選択どおりになること。アプリを再起動しても Android のフォルダー権限が継続して利用できること。

### RA-05 生成再開

複数ユニットの長文をオンライン TTS で生成する。少なくとも1ユニット完了後に通信を切り、通信エラーによる停止を確認する。通信を戻して再開する。

期待結果は、既存の再開操作により最初の未完了ユニットから続行でき、完成済みファイルと章・ユニット境界が維持されること。審査用のトークン再入力や購入を要求されないこと。停止時の完了ユニット番号と再開位置を記録する。

### RA-06 TTS 提供元

同じ短文を Android 端末 TTS、Edge TTS、Azure Speech、Google Cloud TTS で試聴・MP3 生成する。提供元の設定画面や保存した設定が通常どおり使えることを確認する。

期待結果は、設定済みの各提供元で音声を生成できること。資格情報や利用枠が不足する提供元は、その原因を記録して実施不可とする。審査用権利の問題か、TTS サービス側の問題かを、エラー表示と同一提供元の通常利用時の結果から判断する。

## 5. 更新とオフライン

### 時間に関する共通条件

権利は Worker 発行時から72時間で期限切れになる。起動・フォアグラウンド復帰・「審査用アクセスを更新」はオンライン更新を試みる。アプリを開いている間の定期確認は5分ごとで、残り24時間以下のときに更新を試みる。

72時間試験は実時間で行い、端末の日時は自動設定を維持する。端末時刻を進めると、復旧後のサーバー発行時刻との不整合や巻き戻し検知が混ざるため、この手順での合格証跡には使用しない。現在の実装には実機向けの有効期間短縮スイッチはない。

オンライン状態の再起動・復帰や手動更新が成功すると、72時間の起点が新しくなる。オフライン試験の直前にオンラインで手動更新し、成功確認時刻を `T0` と記録してから通信を切る。試験中は Wi-Fi とモバイル通信の両方を遮断する。

画面に厳密な発行時刻の表示がないため、期限前は `T0 + 71時間`、期限後は `T0 + 72時間5分以降` を目安にする。秒単位の期限境界は署名検証の自動テストで補完する。

### RA-07 期限内のオフライン利用

`T0` 直後に通信を切り、ダウンロード済みの端末 TTS で試聴・MP3 生成する。オフラインのままアプリと端末を再起動し、同じ操作を行う。

期待結果は、審査用アクセスが利用でき、共通トークンを求められずに端末 TTS で処理が完了すること。オンライン TTS の通信エラーは別途記録する。

### RA-08 72時間の期限切れ

RA-07 からオフラインを維持する。`T0 + 71時間` に端末 TTS の試聴・新規生成を確認する。`T0 + 72時間5分以降` にアプリを再起動し、同じ操作を試す。

期待結果は、期限前には利用でき、期限後には審査用アクセスによる新規試聴・生成が制限されること。審査用画面に接続して更新する案内が表示されること。既に出力した MP3 は通常の保存先に存在すること。試験端末は試用・購入権利なしの状態を使用する。

### RA-09 期限後の通信復旧と手動更新

RA-08 の期限切れ状態から通信を戻し、アプリをバックグラウンドから復帰させる。復帰による更新を確認する。別の期限切れ試験ではアプリを開いたまま通信を戻し、5分の確認周期とリクエスト処理時間を待つ。手動の「審査用アクセスを更新」でも確認する。

期待結果は、資格情報が有効なら共通トークンの再入力を求めずに再度利用可能になること。自動・手動それぞれの成功時刻を記録する。継続表示中の自動復旧については5分周期に加え、通常の通信応答時間を見込む。

### RA-10 オンラインでの継続更新

1. `T0` にオンラインで更新する。
2. `T0 + 48時間10分` ごろにオンラインでアプリを復帰させ、更新成功を確認して時刻 `T1` を記録する。
3. 直後に通信を切り、`T0 + 73時間` ごろに端末 TTS で試聴・新規生成する。

期待結果は、元の72時間を過ぎても `T1` から72時間以内のため利用できること。これにより更新後の権利が保存されていることを確認する。

定期更新も確認する場合は、検証用端末でアプリを前面に保ち、スリープと省電力による停止を避けて48時間以上経過させる。残り24時間以下になってからの `/review` 呼び出しを確認し、その成功時刻を `T1` として同じ後続試験を行う。前面維持条件が満たせなかった場合は、その定期更新試験を実施不可として記録する。

### RA-11 初回登録時の通信障害

未登録の端末で通信を切り、有効なトークンの登録を試す。通信復旧後、トークンを再入力して登録する。

期待結果は、障害中には権利が付与されず、通信確認と再試行を促す表示が出ること。復旧後には正常に登録できること。

### RA-12 更新時の一時障害と HTTP 429 / 503

有効な審査用アクセスがある状態で、管理者が専用検証環境の `/review` を一時的に HTTP 429、503 へ応答させる条件を準備する。対象端末の手動更新を行い、オフラインにして端末 TTS で試聴・生成する。正常応答に戻して更新する。

期待結果は、一時障害では保存済みの権利と更新用資格情報が保持され、期限内は利用できること。正常化後はトークン再入力を求めず更新できること。期限切れでも資格情報は保持され、接続復旧後に再確認されること。

応答を制御する検証環境が未準備なら該当ステータスのケースを実施不可とする。通常の通信遮断については RA-07、RA-09、RA-11 で確認する。

## 6. 失効・別端末・再登録

### RA-13 オンラインでの個別失効

1. 端末AとBを同じ共通トークンで順番に登録し、両方の試聴・生成を確認する。
2. 管理者がD1の端末Aの対象行だけに `revoked_at_ms` を設定する。[失効操作](play_review_access.md#deployment-configuration) のパラメーター付き SQL を使用する。
3. 端末Aで「審査用アクセスを更新」を押す。
4. 端末Bでも手動更新して試聴・生成する。

期待結果は、端末Aの更新が拒否され、審査用資格情報と権利が解除されてトークン入力欄が再表示されること。端末Bは継続して利用できること。端末Aでは試用・購入による別の権利がない状態で機能制限を確認する。

### RA-14 オフライン中の失効

端末Aの権利を更新して時刻を記録し、通信を切る。管理者が対象登録を失効する。オフラインの端末Aで試聴・生成した後、通信を戻して手動更新する。

期待結果は、オフライン中は発行済み権利の期限内で利用でき、オンラインで失効応答を受信すると解除されること。オフラインを72時間以上維持する追加確認では、失効応答を受信する前でも期限切れで制限されること。

### RA-15 同一トークンでの再登録

失効済みの端末Aで、引き続き有効な共通トークンを入力する。

期待結果は、新しい更新用資格情報による登録ができること。以前の対象行の失効日時が維持され、新しい登録行が作られること。個別失効後の再登録を許す現在の動作を確認する。

### RA-16 データ消去と再インストール

審査用アクセスを有効にした端末で、Android 設定からアプリのデータを消去して起動する。トークンで再登録し、その後アプリをアンインストール・再インストールする。購入権利のない端末で実施する。

期待結果は、どちらの操作後も審査用の初回入力が必要になり、同じ有効トークンで再登録できること。必要な TTS 設定と出力フォルダー権限は各試験の前提として再設定する。

### RA-17 アクセス終了と再有効化

有効な状態で「審査用アクセスを終了」を押す。ホームと審査用画面を確認し、アプリを再起動する。その後、有効な共通トークンで再登録する。

期待結果は、終了後は元の試用・購入の状態に応じた画面へ戻り、再起動によって審査用アクセスが復活しないこと。共通トークンで再有効化できること。終了は端末の審査用情報を削除する現在の操作であり、D1 の既存登録行は保持される。

### RA-18 共通トークンの交換

管理者が専用検証環境で旧トークンを `REVIEW_ACCESS_TOKEN_PREVIOUS` に設定し、新しい主トークンを設定する。未登録状態で旧・新それぞれの登録を確認する。旧トークンの受付を終了した後、再度旧・新で登録を確認し、交換前から登録済みの別端末も更新する。

期待結果は、重複期間は両方で登録でき、旧トークン受付終了後は旧で失敗し、新で登録できること。既存の有効な更新用資格情報は引き続き更新できること。実値を試験記録へ転記しない。

## 7. 試用・購入との独立性

### RA-19 無料試用の保持

試用中の端末で、開始日・終了日を管理者側の試用記録で確認して記録する。審査用アクセスを有効にし、試聴・生成・再起動を行ってから終了する。

期待結果は、審査用アクセス終了後も元の試用が有効で、開始日・終了日が変化しないこと。表示の残日数には実際の経過時間を考慮する。審査用アクセスが失効した場合も同じ確認を行う。

### RA-20 期限切れ試用の保持

試用が終了し、購入権利のない端末で審査用アクセスを有効化する。機能が利用できることを確認して終了・再起動する。

期待結果は、元の期限切れ試用の状態に戻り、無料試用が最初から再開しないこと。管理者側の試用開始日・終了日が変化しないこと。

### RA-21 購入済み権利の保持

`full_access` が正常に検証済みの端末で、審査用アクセスを開始・終了する。再度審査用アクセスを有効化してから、管理者が審査用登録だけを失効し、端末で更新を行う。最後に再起動と購入の復元を確認する。

期待結果は、どの操作後も購入済み権利で試聴・生成できること。審査用資格情報の失効が購入の取消しや購入情報の消去として扱われないこと。購入情報はテスト環境の Play の購入状態と照合する。

### RA-22 審査用権利が購入として復元されないこと

購入履歴のない端末Aで審査用アクセスを開始して終了する。「購入を復元」に相当する既存の操作を行い、同じ Play アカウントの端末Bでも復元を行う。

期待結果は、審査用アクセスを永久購入として復元せず、`full_access` 購入済みにならないこと。元の試用条件に応じた利用制限が適用されること。

## 8. 表示・配布・運用

### RA-23 3言語の表示

日本語・英語・簡体字中国語に切り替え、入口、登録、認証エラー、有効中、期限切れ、更新、終了を確認する。対象端末の大きな文字サイズでも確認する。

期待結果は、翻訳が表示され、ボタンが操作でき、文字が欠けずに読めること。トークン入力が伏せ字になること。アプリの状態と表示が対応していること。

### RA-24 Play 内部テスト版と英語手順

Play 内部テストから対象ビルドを取得し、アプリ内 Google ログインを行っていない状態で、[英語手順](play_review_access.md#english-play-console-instructions) を順に実施する。準備したサンプルの取り込みから MP3 の保存・再生まで進める。

期待結果は、追加の口頭説明なしで到達でき、購入やアプリ内 Google ログインが要求されないこと。実機で確定した TTS 音声、入力サンプル、出力先の操作を Console 登録文へ反映する。配布版を取得するための Play アカウントの使用状況も記録する。

### RA-25 Google Play 未ログイン端末

追加の対応条件確認として、Google Play 未ログインの実機へ、審査用設定済み APK をインストールする。トークン登録、再起動、手動更新、端末 TTS の試聴・生成を行う。

期待結果は、審査用の認証が端末の Play ライセンス判定によって妨げられず、設定済みの `/review` で完了すること。このケースの証跡は APK 配布として記録する。

### RA-26 回数制限と復旧

専用検証環境で、設定済みの IP 制限に達する回数の誤入力を行う。更新資格情報側の制限も、専用端末で手動更新を繰り返して確認する。制限期間の終了後に正しいトークンで再試行する。別ネットワークの端末Bも確認する。

期待結果は、制限時に HTTP 429 が返り、資格情報が誤って失効扱いされず、有効期限内の権利が利用できること。期間終了後に正常な操作が復旧し、共通トークン全体がロックされないこと。制限は Cloudflare の実行拠点ごとの近似値を含むため、実測の回数・応答・待機時間を記録する。

### RA-27 署名設定の不一致

専用検証環境で、アプリの公開鍵と Worker の署名鍵が一致しない条件を準備する。未登録端末で登録を試みる。既存登録のある別端末でも更新を試み、その後に設定を正常へ戻す。

期待結果は、不一致の署名から新たな権利が有効にならず、確認できない旨の表示が出ること。既存の有効な署名付き権利は期限内で利用できること。設定復旧後に正常に登録・更新できること。鍵以外の `kind`、パッケージ、端末 ID の改変は自動テスト結果も併記する。

### RA-28 秘密情報の記録確認

登録成功、誤入力、更新成功、失効、通信エラーを一度ずつ実施し、Android のアプリログ、Worker の通常ログ、採取した画面・障害票を確認する。

期待結果は、共通トークン、更新用資格情報、秘密署名鍵の実値が記録されていないこと。確認時に検索語として使う秘密値もコマンド引数や共有ログに残さない。暗号化ストレージの内部確認は必要に応じて検証専用ビルドで行い、結果には保存キー名と保存・削除の成否だけを記録する。

## 9. 完了判定と後片付け

RA-01〜24、RA-26〜28 の結果を確認する。RA-25 は Google Play 未ログイン端末の追加確認として結果を併記する。未実施・実施不可の項目が残る場合は、その項目と理由を承認者へ提示する。特に72時間試験と Play 内部テスト版の確認は、実施完了を明示する。
